# 直播看板与复盘原型 · 千机设计系统迁移规格

## 1. 目标与角色

- 主播：直播中快速核对商品事实、观察自身状态；下播后查看需讨论片段和个人改进点。
- 运营：直播中观察开场、投放、商品转化与切品依据；下播后组织线下复盘并确认最终正文。
- 中控：配合商品切换、画面展示、赠品和库存动作。

数据密度为高密度实时看板与中密度编辑详情页。录音、报告生成、实时数据刷新是异步边界；商品事实、录音授权和最终保存是高风险边界。

## 2. 已确认工作流

1. 开播 15 分钟对比同主播近 7 场平均，并回看 15 分钟录屏。
2. 将开播时段与本场优秀时段或其他主播优秀时段对比，查看话术标签占比。
3. 监控付费消耗递增但成交掉量，并回看对应录屏。
4. 单款分别诊断曝光→点击、点击→成交和退款；不同环节使用不同排查维度。
5. 同款同主播话术比例通常接近时，补看情绪状态、分贝和语速环比。
6. 新款参考去年同期上新或前置挂链数据。
7. 切品由数据触发；4–5 小时场次通常最多切 3–4 款。
8. 运营与主播完成线下口头复盘后，运营再确认并保存排班复盘正文。

## 3. 页面信息架构

### 直播中

- 固定商品事实区：材质、颜色、赠品、运费险、更新时间。
- 5 个核心指标：5 分钟 GMV、已付、待付、讲解效率和整场 GMV。
- 实时话术统计：只展示覆盖比例与合规分，不输出 AI 动作建议。
- 引流直播间 TOP 短视频：展示流量占比、已核验卖点与承接机制。
- 运营配置模块：实时库存和审核话术墙二选一，避免同时抢占主播注意力。
- 开播对比、投放归因、单款转化、主播状态和切品分析移至下播复盘链路。

### 下播

- 首页只保留场次信息、开始复盘录音和动态异常列表，不展示整场指标或预设原因。
- 异常列表可按系统识别结果增减；当前原型覆盖开场、投放与成交背离、单款转化和主播状态四种视图。
- 开场视图使用双录屏与话术标签对比，明确区分“数据基准”和“可播放的录屏基准”。
- 投放视图使用5分钟趋势、操作事件与录屏联动；商品切换仅在相关异常中作为事件出现。
- 商品视图先判定异常节点，只展开该节点相关证据；基准按本年同款、去年同款、前置挂链、无基准的优先级动态命中。
- 主播状态视图以话术结构、语速和分贝为主，情绪模型只作低权重辅助信息。
- 录音在不同异常视图间持续悬浮；结束后进入转写、结论和排班复盘正文编辑入口。

### 复盘留存

- 严格沿用原后台完整导航、面包屑、参与人、数据统计、TOP5 商品、复盘内容、问题与需求和保存动作。
- 双角色报告：运营草稿、主播报告。
- 运营最终正文：口头复盘后确认与编辑，不能在讨论前冒充最终结论。
- 证据弹窗：录屏、指标时间线、录音转写。
- 行动表：负责人、验证指标、时限、状态；保存后同步复盘需求。

## 4. Pattern 与路径

- Dashboard + drill-through：异常列表进入对应的录屏/数据证据视图。
- Baseline compare：同主播近 7 场、本场优秀时段、其他主播优秀时段。
- Tabs：运营报告、主播报告、运营最终正文。
- Modal：查看录屏和证据；支持 Esc、焦点归还。
- Async task：录音→转写→关联证据→生成草稿；失败可重试，离开页面可继续。
- Edit/save：运营最终正文保存；失败保留编辑内容，冲突提示版本。
- Realtime recovery：live、stale、offline、reconnecting，显示更新时间和手动重试。

主路径：直播监控 → 异常列表 → 对应证据视图 → 线下录音复盘 → 转写与结论 → 运营确认排班复盘正文。

回退路径：仅查看数据；录音稍后补；报告生成失败后重试；保存失败保留草稿。

权限路径：主播只读运营最终正文和行动项；运营可编辑并保存；录音前必须确认参与者授权。

## 5. Skeleton 尺寸

主规格 1440px；侧栏 208px；顶栏 64px；内容边距 24px；24 栅格 gutter 16px。

| 区域 | 成功态尺寸 | Skeleton 对应 |
|---|---:|---|
| 指标卡 | 5 × 164px 宽，112px 高 | label / value / unit / scope / source 五段 |
| 商品事实 | 1184 × 120px | 标题行 + 4 列事实 |
| 实时话术 | 7 栅格 × 300px | 标题、合规分、3 组覆盖进度 |
| 引流短视频 | 10 栅格 × 300px | 标题、2 条视频、卖点机制、承接说明 |
| 配置模块 | 7 栅格 × 300px | 库存/话术 Tabs 与对应内容 |
| 下播异常行 | 100% × 104px | 标签、异常值、基准、偏离和复盘入口 |
| 同屏录屏 | 2 × 12 栅格 | 当前时段与可播放对比时段 |
| 分钟趋势 | 16 栅格 × 300px | 双趋势、异常区间、操作事件 |
| 报告正文 | 8 栅格 × 自适应 | 标题、段落、证据行、行动表 |
| 证据弹窗 | 760 × 560px | 标题、16:9 录屏、指标摘要、转写 |

## 6. 状态矩阵

- 数据容器：loading / success / empty / error。
- 实时页面额外：stale / offline / reconnecting。
- 报告异步：queued / running / succeeded / failed / retrying。
- 编辑：pristine / dirty / saving / saved / conflict / autosave-failed。
- 搜索：no-result；权限：forbidden。

所有状态通过页面顶部“状态演示”入口切换；关键状态不只依赖颜色。

## 7. 组件契约

- 使用项目根目录 `component-contracts.md`。
- 使用 `assets/qianji-tokens.css`。
- Active：App shell、Sidebar/Menu、Topbar/Breadcrumb、Page、Grid、Card、Metric、Tabs、Chart、Table shell、State、Skeleton、Alert、Modal、Toast、Form、Rich text。
- Deprecated：本次不引用任何 deprecated 组件；旧版 `.card/.btn/.kpi/.sidebar` 等自定义 class 全量迁移到 `qj-*` contract。
